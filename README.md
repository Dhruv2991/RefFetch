# Research Copilot — Phase 1

An AI-powered research workspace: upload papers, get auto-summaries, and chat
with your library using retrieval-augmented generation (RAG) so answers are
grounded in your actual papers, not hallucinated.

## What's included in Phase 1

- **Upload PDFs** → text extraction → auto-summary (via Claude) → chunked + embedded for search
- **Chat with one paper or your whole library** — retrieval pulls the most relevant chunks and Claude answers grounded in them, citing `[Source N]`
- **Persistent memory** — every paper you upload stays searchable forever; this is the "remembers everything you've read" feature from the roadmap

## Stack

- Backend: FastAPI, PostgreSQL + pgvector, sentence-transformers (local embeddings, no extra API key), Anthropic Claude for summarization/chat
- Frontend: Next.js 14 (App Router), TypeScript, Tailwind

## Setup

### 1. Database

You need Postgres with the `pgvector` extension. Easiest path — Docker:

```bash
docker run --name research-copilot-db -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=research_copilot -p 5432:5432 -d ankane/pgvector
```

### 2. Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env       # then paste your ANTHROPIC_API_KEY in .env
uvicorn app.main:app --reload
```

Backend runs at `http://localhost:8000`. Visit `http://localhost:8000/docs`
for the interactive API docs (auto-generated by FastAPI — very useful while
you build).

First run will download the local embedding model (~80MB), and creating the
Postgres tables + `vector` extension happens automatically on startup.

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

Visit `http://localhost:3000`.

## How the RAG pipeline works (so you can extend it)

1. On upload: PDF → raw text → split into ~1000-character overlapping chunks → each chunk embedded locally → stored in Postgres as `vector(384)` columns
2. On chat: your question is embedded the same way → pgvector finds the 5 most similar chunks (cosine distance) → those chunks + your question go to Claude as context → Claude answers, grounded in your library
3. Chat history is stored per-paper (or globally, if you're chatting across your whole library) so follow-up questions have context

This is the core loop everything else in the roadmap builds on.

## Known Phase-1 limitations (by design, to keep this shippable)

- No authentication yet — single-user, local only
- Scanned/image-only PDFs won't extract text (no OCR yet)
- Title detection is naive (first long line of text) — Phase 2 can ask Claude to extract real title/authors
- No streaming responses yet — answers arrive all at once
